# TKT-M20-03 - Add Seasonal/Speculative Portfolio Tracking and Staged Exits

GitHub issue: #91

## Milestone

M20 - Personal Learning and Investments

## Goal

Track medium/long-term positions separately from short-term flips and support
manual staged exit decisions with historical/risk context.

## Functional outcome

The user can record/edit/close a position with quantity, known/unknown basis,
thesis, strategy, targets, current net liquidation value, unrealized P&L, and
receive `HOLD`, `SELL PARTIAL`, or `SELL` evidence without spreadsheets. Open
positions also become high-priority inputs to owned market-history collection.

## Dependencies

TKT-M15-03, TKT-M19-01, TKT-M19-03.

## Recommended Codex configuration

Risk class: **R3 (financial/product)**.

- Implementation: Sol High preferred.
- Review: fresh flagship XHigh.

## Requirements

- Position model follows `data-model.md` and preserves partial exits/history.
- Configurable target levels and strategy/category.
- Historical price/supply/liquidity context.
- Opportunity-cost/exposure context.
- Register open-position item IDs through M18's extensible sampling-source
  contract. Editing or partially exiting an open position preserves eligibility;
  closing removes only the position-derived reason so another active source can
  still keep the item eligible.
- Short-term realized flip reporting not polluted by unrealized investment thesis.

Reference use case may include seasonal Festival of the Four Winds inventory,
but generic logic must not hardcode one item's economics.

## Acceptance criteria

- [ ] Add/edit/partial-exit/close position workflow.
- [ ] Unknown basis remains explicit.
- [ ] Current gross/net liquidation/unrealized values distinct.
- [ ] Exit targets configurable.
- [ ] Historical evidence/reasons shown.
- [ ] Open held positions enter the highest-priority collection tier, remain
  eligible through edits/partial exits, and lose only position-derived
  eligibility when closed.
- [ ] No language assuming seasonal scarcity guarantees appreciation.

## Validation

- Run persistence/domain/API/UI tests for add, edit, partial exit, close,
  restart, known/unknown basis, target, strategy/category, history retention,
  and sampling-source registration/removal including overlapping eligibility
  from another source.
- Run independent gross/net liquidation, unrealized P&L, opportunity-cost,
  exposure, and staged-action vectors.
- Run component/accessibility and representative Playwright investment journeys;
  inspect wording for unsupported appreciation guarantees.

## Non-goals

Automated execution, guaranteed seasonal appreciation, or mixing unrealized
investment thesis with realized flip accounting.
