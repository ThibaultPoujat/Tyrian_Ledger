# TKT-M10-01 - Generate a Versioned Public Market Snapshot

## Goal

Extract the bounded public market-data collection from the player scan and
provide a .NET CLI that emits a versioned static snapshot for GitHub Pages.
The CLI is the only new path that obtains live Guild Wars 2 data; it must use
the existing typed gateway and produce no secrets or personal data.

## Dependencies

- TKT-M10-00 is merged, including its ADR and VERIFY baseline.

## Acceptance criteria

- Extract a bounded, reusable public snapshot collection path from the player
  scan without allowing feature code to construct ArenaNet URLs.
- Add a documented, versioned `market-snapshot.json` contract containing only
  public market fields required by browser recommendations, generated-at
  timestamp, contract version, and compatibility metadata.
- Add a deterministic .NET generator CLI that writes the complete snapshot to
  a caller-provided artifact path and exits non-zero for invalid/incomplete
  data. It must not need or emit a player API key, account data, or preferences.
- Enforce the M10 capture policy: two requests per second, at most two
  concurrent requests, and a burst budget of 20. Make implementation details
  visible enough for scheduled-run evidence and future adjustment.
- Preserve external DTO/domain-model separation and C# integer-copper
  calculation semantics.
- Update relevant VERIFY evidence without asserting unverified batching,
  schema, rate-limit, retry, or fee behaviour as fact.

## Required tests and validation

- Unit tests for snapshot contract serialization, version/metadata validation,
  deterministic ordering, and rejection of incomplete data.
- Gateway/orchestration tests that prove bounded collection and configured rate
  and concurrency limits without live Guild Wars 2 calls.
- CLI integration tests using a fake typed gateway and a temporary artifact
  directory; inspect that no secret or personal field is serialized.
- Run focused .NET tests and the repository-required formatter/analyzers.
- Run `git diff --check` and inspect generated JSON fixtures manually.

## Non-goals

- Browser parsing or React UI changes.
- Publishing snapshots, adding a workflow, or changing GitHub Pages settings.
- Collecting player/account data or retaining a snapshot history service.
