# TKT-M10-05 - Publish Static Pages Through Trusted Workflows

## Goal

Add the secure GitHub Actions and GitHub Pages delivery path: generate a
complete static snapshot every 15 minutes, publish one shared Pages site, and
support reviewed selector-config previews of an open same-repository PR SHA.

## Dependencies

- TKT-M10-04 is merged and the repository has only the static site and
  generator delivery surfaces required by M10.

## Acceptance criteria

- Define least-privilege, pinned, documented GitHub Actions workflows that
  generate and publish a complete compatible snapshot every 15 minutes under
  the M10 request, concurrency, and burst policy.
- Keep the workflow and Pages artifact free of secrets, player data, API keys,
  local paths, and logs containing sensitive values. Use no credentials unless
  a separately approved, documented need exists.
- Build and deploy only static React assets and `market-snapshot.json` to a
  single Pages deployment. The published browser bundle must have no Guild Wars
  2 or local `/api` request path.
- Implement the selector as reviewed config-only data on `develop`. The trusted
  publishing workflow must independently confirm that the selected immutable
  SHA belongs to an open code PR in this repository before use.
- Ensure invalid, absent, closed, merged, cross-repository, mutable-ref, or
  malformed selection resolves safely to the current `develop` SHA. Untrusted
  pull-request code must never obtain publishing credentials or control the
  deployment workflow.
- Document deployment operation, delay/failed-capture behaviour, selector
  review, rollback/fallback, cache expectations, and the explicit owner step
  to make the repository and Pages site public. Before advising that owner
  action, run and record the ADR-008 public-history secret-audit gate and the
  targeted workflow and static-artifact review.
- Update VERIFY with actual schedule/run evidence and any remaining externally
  unresolved API behaviour; do not invent confirmations.

## Required tests and validation

- Validate workflow YAML, least-privilege permissions, action pinning policy,
  and static artifact contents in CI-friendly tests or scripts.
- Unit/integration tests for selector parsing and every acceptance/fallback
  branch, with GitHub API interactions mocked or isolated behind a typed
  boundary.
- Run an authorized non-production workflow or equivalent dry run that proves
  the generator, artifact assembly, and static build without exposing secrets.
- Search workflow files, artifacts, and built assets for secrets, `/api`, and
  Guild Wars 2 browser endpoints; run `git diff --check`.

## Non-goals

- Changing repository visibility, enabling Pages, merging, or releasing
  without the owner deliberately performing or approving that GitHub action.
- A deployment per pull request, arbitrary branch/ref previews, or untrusted
  `pull_request_target` execution of PR-provided code.
- A dynamic API, data store, authentication system, or secret-based player
  integration.
