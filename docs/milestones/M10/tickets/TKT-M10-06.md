# TKT-M10-06 - Independently Review the Public Pages Release

## Goal

Independently review the completed public GitHub Pages deployment before
release handoff. Confirm the public site, source history, workflows, static
artifact, accessibility, and deterministic recommendation behaviour meet the
M10 contract.

## Dependencies

- TKT-M10-05 is merged and a Pages deployment is available for review.

## Acceptance criteria

- Conduct the review in a fresh, independent task; do not reuse the
  implementation task's conclusion as review evidence.
- Run the full remaining .NET and frontend validation suites, static production
  build, workflow/configuration checks, and all M10-specific golden-vector and
  browser tests.
- Smoke-test the deployed Pages URL with a fresh snapshot, an expired snapshot
  condition where safely reproducible, and the selector fallback/published-SHA
  evidence. Confirm normal browser operation makes no Guild Wars 2 or `/api`
  request.
- Audit the complete public Git history and current tree for secrets, tokens,
  API keys, `.env` material, local paths, and sensitive generated artifacts;
  record tool version, command, scope, and outcome.
- Review the published static artifact and Actions workflows for least privilege,
  untrusted-code publication paths, cache/content safety, malformed snapshot
  handling, and public-data exposure.
- Perform an accessibility review of fresh, loading, malformed, and delayed
  refresh states, including keyboard and screen-reader-relevant messaging.
- Update VERIFY entries with evidence and unresolved limitations, and produce a
  release handoff that names any owner action still required. Do not merge or
  release on behalf of the owner.

## Required tests and validation

- Execute the repository's full documented validation matrix from a clean or
  clean-equivalent environment.
- Run a full-history secret scan such as `gitleaks detect --log-opts="--all"`
  plus targeted review of workflow and published-artifact contents. This is an
  independent repeat of the ADR-008 pre-publication gate, not a replacement for
  it.
- Use browser automation and a manual browser check against the deployed Pages
  URL; capture concise evidence without recording secrets or private data.
- Review the diff and final release documentation with `git diff --check`.

## Non-goals

- Implementing feature changes except minimal, separately approved fixes needed
  to make the review reproducible.
- Merging pull requests, changing repository visibility, changing Pages
  settings, or publishing a release without the owner's deliberate approval.

## Required Codex configuration

Use **GPT-5.6 Terra with XHigh reasoning effort**. This independent review is
