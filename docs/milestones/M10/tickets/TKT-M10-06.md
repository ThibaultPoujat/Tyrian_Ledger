# TKT-M10-06 - Independently Review the Public Pages Release

## Goal

Independently review the completed public GitHub Pages deployment before
release handoff. Confirm the public site, source history, workflows, static
artifact, accessibility, and deterministic recommendation behaviour meet the
M10 contract.

## Dependencies

- TKT-M10-05 is merged and a Pages deployment is available for review.

## Acceptance criteria

- Conduct the review in a fresh, independent task; do not reuse the
  implementation task's conclusion as review evidence.
- Run the full remaining .NET and frontend validation suites, static production
  build, workflow/configuration checks, and all M10-specific golden-vector and
  browser tests.
- Smoke-test the deployed Pages URL with a fresh snapshot, an expired snapshot
  condition where safely reproducible, and the selector fallback/published-SHA
  evidence. Confirm normal browser operation makes no Guild Wars 2 or `/api`
  request.
- Audit the complete public Git history and current tree for secrets, tokens,
  API keys, `.env` material, local paths, and sensitive generated artifacts;
  record tool version, command, scope, and outcome.
- Review the published static artifact and Actions workflows for least privilege,
  untrusted-code publication paths, cache/content safety, malformed snapshot
  handling, and public-data exposure.
- Perform an accessibility review of fresh, loading, malformed, and delayed
  refresh states, including keyboard and screen-reader-relevant messaging.
- Update VERIFY entries with evidence and unresolved limitations, and produce a
  release handoff that names any owner action still required. Do not merge or
  release on behalf of the owner.

## Required tests and validation

- Execute the repository's full documented validation matrix from a clean or
  clean-equivalent environment.
- Run `gitleaks detect --source . --log-opts="--all" --redact --no-banner`
  plus targeted review of workflow and published-artifact contents. This is an
  independent repeat of the ADR-008 pre-publication gate, not a replacement for
  it.
- Use browser automation and a manual browser check against the deployed Pages
  URL; capture concise evidence without recording secrets or private data.
- Review the diff and final release documentation with `git diff --check`.

## Non-goals

- Implementing feature changes except minimal, separately approved fixes needed
  to make the review reproducible.
- Merging pull requests, changing repository visibility, changing Pages
  settings, or publishing a release without the owner's deliberate approval.

### Public Pages evidence

The owner made the repository public and enabled GitHub Pages from Actions after the independent audit. The first
deployment exposed a Pages-base-path defect: the React build read variables written to `GITHUB_ENV` in the same step,
so it emitted root-relative asset URLs. The separately approved, minimal correction moved configuration export into
the prior step; it was reviewed and merged as [PR #61](https://github.com/ThibaultPoujat/Tyrian_Ledger/pull/61).

The successful rerun [33635230439](https://github.com/ThibaultPoujat/Tyrian_Ledger/actions/runs/33635230439) deployed
from source `0f093969b1e63e77df933c9fe482f20e8163ed04`. With the selector preserved as `null`, the trusted selector log
records `develop` fallback to that exact SHA. The generator completed with the public `2 requests/s`, `2 concurrent`,
and `20` burst capture policy; the audited candidate was deployed successfully. The public
[Pages site](https://thibaultpoujat.github.io/Tyrian_Ledger/) serves repository-relative assets and a snapshot generated
at `2026-09-02T13:29:51.1790793Z`.

The run also exposed a GitHub-hosted runner warning for the old Node 20 artifact-action releases. The workflow now pins
the reviewed Node 24 releases of direct artifact transfer and Pages configuration, packaging, and deployment actions;
the workflow contract locks those exact immutable SHAs. This preserves the existing permissions and artifact policy.

After the push deployment, GitHub did not create the expected scheduled events even though the active workflow was on
the `develop` default branch and Pages/Actions settings were enabled. The owner authorized an offset 15-minute cadence
(`7,22,37,52` UTC) and a `workflow_dispatch` recovery trigger. The latter follows the same trusted path and restores
fresh data when an owner selects **Run workflow**, but does not substitute for scheduled-run evidence.

The owner-authorized rerun of [33635230439](https://github.com/ThibaultPoujat/Tyrian_Ledger/actions/runs/33635230439)
completed successfully at 14:09 UTC and restored the public snapshot generated at
`2026-09-02T14:08:06.6071078Z`. It is a recovery deployment of the push-triggered workflow, not scheduled-run evidence.

An isolated clean-browser review of that public URL confirmed a fresh compatible snapshot, stable locally calculated
recommendations after reload, keyboard navigation to Settings and back, and no browser request to `/api` or a
`guildwars2.com` host. It also intercepted only the deployed snapshot response to reproduce loading, delayed, and
malformed states. Each presented the expected accessible status or alert, suppressed recommendation cards when data
was stale or malformed, retained keyboard navigation, and had no automated Axe WCAG 2.2 AA violations.
