# TKT-M10-03 - Serve the Static Snapshot Experience

## Goal

Convert the React experience from a player-triggered scan to the timestamped
static snapshot contract. The UI must visibly distinguish fresh data from a
delayed refresh and work under static hosting with no API server.

## Dependencies

- TKT-M10-02 is merged, including the browser parser and exact `BigInt`
  recommendation engine.

## Acceptance criteria

- Load the timestamped static snapshot through a deployment-safe, configured
  asset path and recalculate recommendations locally from browser-local capital
  and risk preferences.
- Remove player-triggered scan controls and all browser dependence on a local
  `/api` endpoint or Guild Wars 2 endpoint.
- Display the snapshot generation time and an understandable loading,
  compatible-data, malformed-data, and delayed-refresh state.
- At more than 30 minutes old, make the snapshot non-actionable: show the
  delayed-refresh state and suppress every recommendation rather than showing
  stale opportunities.
- Preserve accessibility, keyboard operation, useful empty/error messaging,
  and exact integer-copper display behaviour.
- Convert browser tests to run against static fixtures/assets only; test
  network routing so no application request reaches `/api` or Guild Wars 2.
- Update relevant VERIFY evidence without asserting unverified external facts.

## Required tests and validation

- Component/unit tests for freshness at 30-minute boundaries, future timestamps,
  incompatible versions, invalid data, and preference changes.
- Static Playwright tests for fresh, stale, malformed, and unavailable snapshot
  states, including accessibility checks and network-request assertions.
- TypeScript checks, frontend test suite, static production build, and
  `git diff --check`.

## Non-goals

- Removing ASP.NET, SQLite, migrations, or the local two-process developer
  runtime; TKT-M10-04 owns retirement.
- Adding Pages workflows, PR selector publication, or public repository
  settings.
