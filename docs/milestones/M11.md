# M11 - Published Snapshot Reliability

## Goal

Keep the public static Pages snapshot refreshed through an independent,
observable 15-minute trigger without adding a dynamic application service,
browser network path, Guild Wars 2 client, account system, or stored player
data.

## Product and architecture decisions

- Cloudflare Worker Cron is the sole periodic trigger. At minutes 7, 22, 37,
  and 52 UTC it requests a `workflow_dispatch` of the trusted Pages workflow on
  `develop`.
- GitHub Actions remains the only live Guild Wars 2 client and performs the
  existing bounded `2 requests/s`, two-concurrent, burst-20 capture.
- The Worker is private, has no HTTP feature, does not read the public
  snapshot, and can call only GitHub's App-token and fixed workflow-dispatch
  endpoints.
- A repository-scoped GitHub App with only Actions write permission authenticates
  the Worker. Its credentials exist only as encrypted Cloudflare Worker secrets.
- A slow Pages capture completes rather than being cancelled by the next
  interval; only the newest pending refresh is retained.
- Cloudflare error alerts, GitHub Actions failure notifications, the existing
  30-minute stale-data UI state, and manual dispatch are the layered recovery
  controls. None gives an absolute external-service availability guarantee.

## Completion rule

M11 is complete only when two consecutive Cloudflare Cron invocations have
created successful trusted Pages workflow-dispatch runs, each publishes a fresh
validated snapshot, and the corresponding evidence and platform alerts are
recorded under VERIFY-015. The owner retains control of Cloudflare, GitHub App,
secret, deployment, and merge decisions.

## Non-goals

- A dynamic hosted API, database, user account, browser worker, or browser
  network request.
- Guild Wars 2 access from Cloudflare or the browser.
- A credential in source, tests, fixtures, workflow configuration, logs, or
  Git history.
- A promise of absolute availability from Cloudflare or GitHub.
