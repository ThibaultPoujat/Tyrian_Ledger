# TKT-M13-01 - Add the Local ASP.NET Core Application Host

GitHub issue: #69

## Milestone

M13 - Local Runtime and Authenticated Read-Only Gateway

## Goal

Create the loopback local runtime that React will use instead of the retired
static snapshot delivery.

## Functional outcome

The user can start one local application environment; the ASP.NET Core host is
healthy without an ArenaNet key, React can communicate with it, and built React
assets can be served locally for normal use.

## Dependencies

TKT-M12-03.

## Recommended Codex configuration

Risk class: **R3 (architecture/security/network boundary)**.

- Implementation: Sol High preferred; Terra High acceptable.
- Review: fresh flagship XHigh.

## Requirements

- Add a small ASP.NET Core host project to the solution.
- Bind explicit IPv4/IPv6 loopback addresses only by default; normal
  configuration must reject wildcard/LAN listeners.
- Validate `Host` through an explicit allowlist (`AllowedHosts` or equivalent)
  to protect the loopback service from DNS rebinding.
- Add health/status endpoint.
- Document development React integration (proxy/dev server or equivalent) with
  CORS limited to exact configured trusted development origins.
- Provide local production path serving built frontend assets and API from the
  same origin.
- Establish explicit cross-origin request/anti-forgery protection for all
  current and future state-changing local endpoints; CORS alone is not CSRF
  protection.
- Keep business logic out of endpoints.
- Start safely with no ArenaNet key/database feature configured.
- Add host startup/health integration tests.

## Acceptance criteria

- [ ] One documented command/short sequence starts local development.
- [ ] Host starts without ArenaNet key.
- [ ] Health endpoint succeeds.
- [ ] React can call a safe local endpoint.
- [ ] Default binding is loopback, not LAN/Internet.
- [ ] Unapproved Host values and DNS-rebinding-shaped requests are rejected.
- [ ] Development CORS accepts only exact trusted origins and rejects arbitrary
      origins; production frontend/API are same-origin.
- [ ] Representative state-changing requests reject untrusted cross-origin
      requests independently of CORS.
- [ ] Built frontend can be hosted locally through the target same-origin path.
- [ ] Architecture/current docs reflect concrete host project.

## Validation

- Host integration tests cover IPv4/IPv6 loopback defaults and rejection of
  wildcard/non-loopback normal configuration.
- Integration tests cover allowed and spoofed Host headers, exact trusted and
  untrusted development origins, production same-origin behavior, and
  state-changing-request anti-forgery/cross-origin rejection.
- Startup/health tests run with no ArenaNet key, and frontend build plus the
  React/local-API integration contract pass.
- These integration tests are a prerequisite for starting TKT-M13-02.

## Non-goals

SQLite, key storage, account endpoints, scanner/recommendation logic.
