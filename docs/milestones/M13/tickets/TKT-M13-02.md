# TKT-M13-02 - Add Secure Local ArenaNet API-Key Validation and Permission Status

GitHub issue: #70

## Milestone

M13 - Local Runtime and Authenticated Read-Only Gateway

## Goal

Allow the local host to use a dedicated ArenaNet API key without exposing or
persisting the secret incorrectly.

## Functional outcome

The user can configure a key through the supported local secret path and see
safe configured/valid/permission status in the UI; missing or invalid keys fail
cleanly and do not prevent non-account app startup.

## Dependencies

TKT-M13-01.

## Recommended Codex configuration

Risk class: **R3 (security)**.

- Implementation: Sol High preferred; Terra High acceptable.
- Review: fresh flagship XHigh.

## Requirements

- Use ADR-006 OS-backed secret mechanism; environment variable only as documented development/test fallback.
- Validate with verified token-info/equivalent endpoint.
- Return only safe status/permission metadata to React.
- Redact secret/authorization data from logs/errors.
- Handle missing, revoked/malformed, and insufficient-permission cases.
- Preserve read-only boundary.

## Acceptance criteria

- [ ] Key value never appears in browser payload/storage, SQLite, logs, fixtures, source, or test snapshots.
- [ ] Missing key does not prevent safe app startup/public-market capability.
- [ ] UI/API can explain unavailable account features without revealing secret.
- [ ] Required permissions are documented/verified or tracked in VERIFY.
- [ ] Valid/missing/invalid/insufficient-permission tests exist.
- [ ] Malicious token metadata is rendered/returned safely as data, not executable markup.

## Validation

Secret non-disclosure, valid key fixture, missing permission, malformed/revoked
response, malicious metadata, logging/error redaction, and the passing
TKT-M13-01 Host/origin/anti-forgery integration suite.

## Non-goals

Importing transactions/inventory or storing account snapshots.

## Delivery and review

Functional summary explains how the user connects safely. Fresh flagship XHigh
security review required. Keep the summary to the required 2-6 sentences and,
before delivery, update `CURRENT.md` to TKT-M13-03 or an explicit valid handoff.
