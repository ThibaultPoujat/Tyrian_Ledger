# M10 - Static GitHub Pages Snapshot Deployment

## Goal

Make Tyrian Ledger usable without a locally running application by publishing a
static, public GitHub Pages site backed by a periodically generated market
snapshot. The browser must remain a static client: it must not call Guild Wars
2 endpoints or a local `/api`.

## Product and architecture decisions

### Public deployment model

- The repository becomes public before the GitHub Pages deployment. The
  complete source and its Git history, as well as the user-facing site, must be
  treated as public.
- GitHub Actions is the only live Guild Wars 2 API client. It produces a
  complete, publishable market snapshot every 15 minutes.
- GitHub Pages serves only static React assets and `market-snapshot.json`.
  There is no hosted ASP.NET API, database, server-side preference store, or
  browser-to-Guild-Wars-2 network path.
- The capture policy is deliberately conservative: no more than two requests
  per second, at most two concurrent requests, and a burst budget of 20. The
  external batching, schema, rate-limit, retry, and fee uncertainties remain
  explicitly tracked in the VERIFY register until verified.

### Snapshot behaviour

- The versioned snapshot contract includes the full public market data required
  for recommendations, its generation timestamp, and enough metadata for the
  browser to reject incompatible data.
- A snapshot older than 30 minutes is non-actionable. The application clearly
  presents a delayed-refresh state and produces no recommendations until a
  fresh compatible snapshot is available.
- Capital and risk settings remain browser-local preferences. The browser
  recalculates recommendations with `BigInt` so all money and fee behaviour
  remains exact integer copper.

### Shared PR-preview selector

- Pages has one shared deployment rather than one site per pull request.
- A reviewed, config-only selector pull request targeting `develop` may choose
  the immutable SHA of an open code pull request from this same repository.
- A trusted workflow, not untrusted pull-request code, validates the selector
  before publishing it. Closed, merged, invalid, or untrusted selections fall
  back to `develop`.

### Governance

- A new ADR will supersede only the local-runtime assumptions in ADR-001 and
  ADR-002. The existing M9 records remain historical evidence and are not
  rewritten.
- M10 retains the typed Guild Wars 2 gateway and the read-only boundary. It
  never places secrets in source, workflow artifacts, logs, browser storage,
  tests, fixtures, or Git history.

## Completion rule

M10 is complete only when a public GitHub Pages deployment serves a fresh,
validated static snapshot; all normal interactions work with no local backend;
the trusted selector flow is validated; and an independent review records the
security, accessibility, secret-history, and release evidence. The repository
owner retains control of repository visibility, GitHub Pages settings, and
merging or releasing any pull request.

## Non-goals

- Hosting a dynamic API, a database, or a personal account service.
- Sending Guild Wars 2 requests from browser code.
- Providing one public deployment per pull request, arbitrary ref selection,
  or deployment from untrusted workflow code.
- Changing financial policy, performing trades, or adding account/API-key
  functionality.
- Retaining historical snapshots beyond the currently published artifact.
