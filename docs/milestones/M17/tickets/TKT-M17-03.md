# TKT-M17-03 - Build the Live Scanner UI and Watchlist Workflow

GitHub issue: #81

## Milestone

M17 - Live Market Intelligence

## Goal

Make current scanner evidence practical to use and define the high-interest set
for future historical collection.

## Functional outcome

The user can filter/sort current candidates, inspect exact economics and
liquidity risk, open order-book detail, and maintain a durable local watchlist.

## Dependencies

TKT-M17-02.

## Recommended Codex configuration

Risk class: **R2**.

- Implementation: Terra High or Sol High.
- Review: fresh Sol High.

## Requirements

Scanner UI includes applicable:

- item/current bid/ask;
- exact net profit/ROI;
- max bid;
- depth/liquidity evidence and flags;
- current suggested quantity/capital evidence available at this milestone;
- freshness;
- filters for ROI/profit/price/capital/liquidity;
- local durable watchlist add/remove;
- item detail/order-book context.

React does not recompute financial truth.

## Acceptance criteria

- [ ] User can find actionable current candidates without manual calculations.
- [ ] Rejection/risk reasons are visible.
- [ ] Filters/sort/detail/watchlist interactions tested.
- [ ] Watchlist is durable through local backend/persistence, not browser-only authoritative state.
- [ ] Accessible loading/error/empty states.
- [ ] No historical-stability/final `What Should I Do?` scope creep.

## Delivery and review

Functional summary explains the scanner workflow the user can now perform.
Fresh review required before merge.
