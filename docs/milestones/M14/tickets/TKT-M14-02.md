# TKT-M14-02 - Implement Idempotent Personal Trading Post Synchronization

GitHub issue: #73

## Milestone

M14 - Durable Personal Data

## Goal

Synchronize personal TP data into SQLite repeatedly without duplicate history or
loss of previously valid state.

## Functional outcome

The user can run sync many times; new completed transactions are retained,
current orders reflect the last successful complete sync, remote history aging
does not erase local history, and partial failures do not wipe good data.

## Dependencies

TKT-M13-03, TKT-M14-01.

## Recommended Codex configuration

Risk class: **R3 (state/data loss)**.

- Implementation: Sol High preferred.
- Review: fresh flagship XHigh.

## Requirements

- Upsert completed transactions by authoritative external ID/account scope.
- Reconcile current-order state only after complete successful reads.
- Do not interpret disappearance as completed trade without completed-history evidence.
- Track sync status/time/history coverage.
- Preserve old imported transactions after remote window moves.
- Keep account scopes isolated.

## Acceptance criteria

- [ ] Repeat sync creates no duplicate completed transactions.
- [ ] New completed transactions append/upsert correctly.
- [ ] Current orders update only from successful complete sync.
- [ ] Failed/partial sync cannot wipe prior good state.
- [ ] Remote-history aging cannot delete local completed history.
- [ ] Removed current order is not silently counted as completed.
- [ ] Tests cover first/repeat/new/remove/partial-failure/account-isolation cases.

## Non-goals

Profit matching, market history, dashboard polish.

## Delivery and review

Functional summary describes durability/idempotency behavior, not just endpoints.
Fresh flagship XHigh data-integrity review required.
