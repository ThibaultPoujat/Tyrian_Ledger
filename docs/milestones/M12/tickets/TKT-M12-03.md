# TKT-M12-03 - Establish the Post-Pivot Quality Baseline

GitHub issue: #68

## Milestone

M12 - Controlled Personal-Assistant Pivot

## Goal

Create a trustworthy known-good checkpoint after static-runtime retirement and
before new local/private data surfaces are introduced.

## Functional outcome

A clean checkout has documented commands that build/test the active C# and React
projects, secret scanning passes, and `CURRENT.md` hands the project cleanly to
M13.

## Dependencies

TKT-M12-02.

## Recommended Codex configuration

Risk class: **R1**.

- Implementation: Terra High.
- Review: fresh Terra High.

## Acceptance criteria

- [ ] Active .NET solution builds cleanly from clean checkout.
- [ ] Active frontend builds cleanly.
- [ ] All active tests pass or a real blocker is documented.
- [ ] Gitleaks/full relevant secret scan passes.
- [ ] No retired Pages/static-runtime code remains accidentally in the active build/CI.
- [ ] Exact validation commands are documented.
- [ ] `CURRENT.md` records the baseline and TKT-M13-01 as next.
- [ ] No new product feature is added.

## Validation

Run the full active test/build matrix and secret scan defined by the updated
repository docs/CI. Inspect clean-checkout assumptions.

## Non-goals

Changing runtime behavior beyond repairs needed to restore the post-pivot
baseline.

## Delivery and review

Functional summary should state whether the project is clean and ready for M13,
including any carried limitation, in the required 2-6 sentences. Before
delivery, update `CURRENT.md` to TKT-M13-01 or an explicit valid handoff. Fresh
review required before merge.
