# TKT-M21-02 - Implement Owned-Material Opportunity Cost and Crafting Economics

GitHub issue: #93

## Milestone

M21 - Mes Signaux and Crafting Intelligence

## Goal

Establish the deterministic economic truth used by crafting plans: owned materials are assets, never free inputs, and direct ingredient procurement is valued against realistic alternatives.

## Functional outcome

For a feasible craft, the application can compare consuming owned tradable materials against selling them, value direct missing-input procurement, and return exact fee-aware economic profit/ROI/break-even primitives that later bounded recipe planning can compose.

## Dependencies

TKT-M15-01, TKT-M21-01, TKT-M21-S05 / #133.

## Recommended Codex configuration

Risk class: **R3 (financial)**.

Review path: **SOL-GATED** — Terra High implementation/fixes; create a Draft PR and keep it Draft until required validation/CI is green and a fresh separate Sol XHigh review returns APPROVE.

## Requirements

For each direct ingredient quantity determine, where evidence permits:

- owned quantity;
- realizable sale/opportunity value for owned tradable quantity;
- current instant-buy acquisition cost for missing tradable quantity;
- economically bounded buy-order acquisition option for missing tradable quantity when the caller evaluates a waiting/passive procurement strategy;
- bound/non-sellable handling;
- explicit unknown/unavailable-price/insufficient-evidence states;
- exact mixed owned + acquired quantity economics.

For a craft compute:

- economic input cost using owned-material opportunity cost rather than zero;
- direct-procurement strategy/evidence supplied for each ingredient;
- output gross sale value;
- exact canonical TP fees;
- net sale proceeds;
- economic profit;
- ROI;
- break-even output price;
- comparison against the realistic alternative of selling owned tradable inputs instead of consuming them.

The economic primitive must be composable by TKT-M21-03 / #94: a recursively crafted intermediate can later be supplied as another acquisition alternative without changing the opportunity-cost rules here. This ticket does not perform recursive recipe-graph search itself.

## Acceptance criteria

- [ ] Owned tradable materials contribute realizable opportunity value rather than zero cost.
- [ ] Direct instant-buy, bounded buy-order, owned, and mixed owned/acquired inputs are modeled exactly when evidence is available.
- [ ] Consuming an owned material cannot make a craft appear profitable when selling that material is economically superior under the same evidence.
- [ ] Unknown/non-tradable/bound/unavailable inputs produce explicit uncertainty/feasibility states.
- [ ] Tests cover owned, instant-bought, buy-order, mixed, bound, unavailable-price, raw-sale-alternative, fee, break-even, quantity, rounding and overflow cases.
- [ ] Gross output price alone can never mark a craft profitable.
- [ ] Browser code does not duplicate crafting financial formulas.

## Validation

- Independently derived owned, instant-buy, buy-order, mixed, bound and unknown/unavailable vectors.
- Raw-input sale alternative vectors, including cases where crafting must lose.
- Canonical output-fee, break-even, quantity, rounding and overflow vectors.
- Canonical fee-policy regression suite; keep VERIFY-013 provisional disclosure if still open.
- Verify frontend code only renders backend economics and contains no duplicate crafting formula.

## Non-goals

- Recursive intermediate-crafting/path search; that belongs to #94.
- Crafting UI.
- Automated gameplay/crafting or Trading Post mutations.
