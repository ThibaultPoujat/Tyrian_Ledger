# TKT-M21-03 - Add Bounded Crafting Opportunity Paths and Guided Artisanat UI

GitHub issue: #94

## Milestone

M21 - Mes Signaux and Crafting Intelligence

## Goal

Turn crafting capability, economic input valuation, recipe graphs and market evidence into bounded profitable crafting plans that plug into the `Mes Signaux` plan model instead of a giant recipe-analysis table.

## Functional outcome

The user can open `Artisanat` when they deliberately want to spend time crafting for profit, compare a small number of guided executable plans, and start paths that use the shared plan/step/resource/reconciliation model. Strong craft opportunities can also surface in `Mes Signaux` when they pass the same attention gate.

## Dependencies

TKT-M19-01, TKT-M21-02 / #93, TKT-M21-S05 / #133.

## Recommended Codex configuration

Risk class: **R3 (financial/algorithmic)**.

Review path: **SOL-GATED** — Terra High implementation/fixes; Draft PR; required validation/CI green before fresh separate Sol XHigh review; targeted fresh Sol re-review after scoped fixes.

## Requirements

- Reuse/refine the historical bounded recipe-graph design where compatible.
- Respect verified discipline levels, recipe unlocks and current crafting capability.
- Detect recipe graph cycles.
- Apply configurable recursion/candidate limits and report truncation explicitly.
- Memoize repeated subproblems.
- For each missing ingredient choose the best supported economic acquisition alternative from:
  - already owned quantity at opportunity cost;
  - instant-buy market acquisition;
  - buy-order procurement when a waiting/passive strategy is being built;
  - recursively craft an intermediate when feasible and economically superior.
- `Mixed procurement` is an internal optimization result, not a user-selected mode.
- Use #93 economic primitives consistently for owned materials, direct acquisition, fees, break-even and raw-material sale alternatives.
- Include output liquidity, depth, retained history and confidence before a theoretical craft margin can become actionable.
- Where verified evidence permits, expose relevant recipe-unlock acquisition cost/payback without inventing unavailable contracts.
- Emit craft opportunities/plans compatible with #133 resource reservations and Active/Passive semantics.
- Passive example: place ingredient buy orders, then wait; a later fill can generate a new Active craft/list path.
- Active chains must be immediately executable. A buy-order step may appear only as a terminal step that does not block later immediate steps.

## Artisanat UI

- `Artisanat` is the deliberate workspace for the user who wants to spend time crafting for profit.
- Present a small number of guided profitable plans, not an exhaustive sortable world table as the primary interaction.
- Show plan-level modeled profit, capital required, confidence, interaction time and key feasibility/liquidity evidence, with progressive detail.
- Once started, use the shared plan/step execution and reconciliation model rather than crafting-specific manual bookkeeping.
- Crafting opportunities may also surface in `Mes Signaux` when they pass the same attention gate and fit current state.
- All user-facing labels, actions, explanations, errors, empty states and accessibility text introduced/touched are French.

## Acceptance criteria

- [ ] Simple, multi-step, alternative-path and cycle test vectors.
- [ ] Depth/candidate truncation is explicit.
- [ ] Owned/instant-buy/buy-order/intermediate-craft alternatives are compared consistently under #93 economics.
- [ ] Raw-material sale can correctly beat crafting and suppress the craft opportunity.
- [ ] Output liquidity/history/confidence can reject a nominally high-margin but weakly realizable craft.
- [ ] Generated craft plans reserve resources compatibly with #133.
- [ ] Active craft plans do not contain a blocking buy-order step before later immediate steps.
- [ ] `Artisanat` presents guided plans and progressive detail without recomputing financial truth in React.
- [ ] Representative French UI and Playwright journeys cover no-opportunity, passive procurement, active multi-step craft, truncation and degraded-evidence states.
- [ ] No exhaustive world optimization or automation.

## Validation

- Algorithm vectors: simple, multi-step, alternative path, cycle, truncation and memoization.
- Economic vectors across owned/direct/intermediate alternatives.
- Liquidity/history/confidence rejection tests.
- Resource-reservation integration tests with #133 plan model.
- Component/accessibility tests and representative Playwright `Artisanat` journeys.

## Non-goals

- Exhaustive world optimization.
- Gameplay/crafting automation.
- Profitability claims without output liquidity/history evidence.
