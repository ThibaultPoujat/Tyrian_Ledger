# TKT-M15-01 - Establish and Register the Canonical GW2 Trading Post Fee Policy

GitHub issue: #75

## Milestone

M15 - Trustworthy Accounting

## Goal

Turn the existing configurable fee engine into one canonical GW2 application
policy while retaining generic fee primitives, and make its external evidence
status unambiguous.

## Functional outcome

Every backend feature can use one exact, documented fee/rounding policy; React
and feature code no longer need assumptions such as `price * 0.85`. If external
rounding evidence remains insufficient, the app and docs consistently identify
fee-derived results as modeled/provisional rather than verified behavior.

## Dependencies

TKT-M12-03.

## Recommended Codex configuration

Risk class: **R3 (financial)**.

- Implementation: Sol High preferred.
- Review: fresh flagship XHigh.

## Requirements

- Seek sufficient authoritative evidence for current fee behavior/rounding and
  record it through the VERIFY process.
- If sufficient rounding evidence is not obtainable, keep VERIFY-013 OPEN and
  preserve the chosen per-fee rounding as an explicit provisional modeling
  assumption in code, docs, UI/result terminology, and tests.
- Keep generic `TransactionFeePolicy` reusable.
- Add canonical application GW2 fee configuration/policy.
- Model listing and exchange components separately.
- Document cancellation/relisting implications.
- Add whole-copper edge/regression vectors.

## Acceptance criteria

- [ ] No scattered canonical fee constants in UI/features.
- [ ] Generic fee tests remain valid.
- [ ] Whole-copper examples/rounding edges pass for the configured policy and
      tests do not claim to verify external behavior by themselves.
- [ ] Very small sale values/quantities are covered.
- [ ] Exactly one completion path is recorded: (a) sufficient authoritative
      evidence resolves VERIFY-013 and verified behavior is named precisely, or
      (b) VERIFY-013 remains OPEN and rounding plus every dependent claim is
      explicitly modeled/provisional.
- [ ] README, trading rules, VERIFY register, milestone language, UI/result
      terminology, and testing policy agree with that evidence status.
- [ ] Browser has no competing fee formula.

## Validation

- Run generic fee-policy tests plus independently derived whole-copper edge,
  minimum-fee, quantity, and overflow/regression vectors.
- Search frontend/backend/docs for scattered fee constants and unsupported uses
  of `verified` or `authoritative` fee language.
- Independently inspect the evidence recorded for VERIFY-013; passing unit tests
  are not external evidence.

## Non-goals

FIFO, dashboard, scanner ranking.

## Delivery and review

Functional summary states the exact user-visible economic capability gained.
It must say whether behavior is externally verified or still provisional and
remain within the required 2-6 sentences. Before delivery, update `CURRENT.md`
to the next valid ticket/handoff. Fresh flagship XHigh financial review must
independently recompute representative fee vectors.
