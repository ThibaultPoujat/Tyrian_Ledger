# TKT-M15-02 - Implement Deterministic FIFO Lot Matching with Partial Fills

GitHub issue: #76

## Milestone

M15 - Trustworthy Accounting

## Goal

Build authoritative FIFO cost-basis reconstruction from completed personal buys
and sells.

## Functional outcome

The application can explain which acquisition lots funded each completed sale,
including partial fills and unknown pre-history inventory, and can rebuild the
same result deterministically from stored transactions.

## Dependencies

TKT-M14-02, TKT-M15-01.

## Recommended Codex configuration

Risk class: **R3 (financial/accounting)**.

- Implementation: Sol High preferred.
- Review: fresh flagship XHigh.

## Requirements

- Completed buys create lots by item/account in deterministic FIFO order.
- Sells consume oldest remaining quantity first.
- Support partial lot, many buys -> one sell, one buy -> many sells.
- Unknown/missing acquisition produces explicit unmatched/unknown basis.
- Persist matches only as rebuildable/versioned derived state if persisted.
- Integer copper and canonical fee policy only.

## Acceptance criteria

- [ ] Complete trade vector.
- [ ] Partial sell vector.
- [ ] Many buys -> one sell vector.
- [ ] One buy -> many sells vector.
- [ ] Interleaved item/account isolation vector.
- [ ] Same-timestamp/tie ordering is deterministic and documented.
- [ ] Missing prior acquisition remains unknown.
- [ ] Rebuild twice is identical.
- [ ] Current/disappeared open orders never become completed inventory without history evidence.

## Validation

- Run independently derived FIFO vectors covering complete, partial,
  many-to-one, one-to-many, interleaved item/account, equal-timestamp, unknown
  basis, and repeat-rebuild cases.
- Run canonical fee-policy tests and persistence tests if derived matches are
  stored.
- Confirm property/order invariants use integer copper and deterministic tie
  breaking.

## Non-goals

Dashboard/charting, alternative accounting policy selection.
