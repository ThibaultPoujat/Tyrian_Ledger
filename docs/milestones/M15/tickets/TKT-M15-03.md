# TKT-M15-03 - Compute Realized P&L, Open Cost Basis, and 7/30/90-Day Performance

GitHub issue: #77

## Milestone

M15 - Trustworthy Accounting

## Goal

Turn FIFO matches and current market evidence into reproducible personal
performance statistics without mixing realized and unrealized economics.

## Functional outcome

The user can know realized net profit/fees/ROI for supported history windows,
what cost basis remains open, and current net liquidation/unrealized value with
unknown coverage clearly disclosed.

## Dependencies

TKT-M15-02.

## Recommended Codex configuration

Risk class: **R3 (financial/accounting)**.

- Implementation: Sol High preferred.
- Review: fresh flagship XHigh.

## Requirements

Calculate separately where evidence supports it:

- realized gross sales;
- listing/exchange fees;
- realized net profit and ROI;
- remaining/open FIFO basis;
- current net liquidation value;
- unrealized P&L;
- 7, 30, 90-day realized results;
- coverage start/limitations.

Unknown basis is excluded/labeled, never zero.

## Acceptance criteria

- [ ] Deterministic rebuild from stored transactions + explicit current market evidence.
- [ ] Realized/unrealized never mixed.
- [ ] Unknown/unmatched lots explicitly handled.
- [ ] Profitable, losing, partial, unsold, unknown-cost tests.
- [ ] 7/30/90 boundary/timezone tests use UTC semantics.
- [ ] No lifetime-profit claim before local coverage.
- [ ] Fee allocation semantics are tested/consistent with canonical policy.

## Validation

- Run independently derived profitable, losing, partial, unsold, unknown-basis,
  coverage-boundary, UTC-window, and fee-allocation unit/integration vectors.
- Run FIFO rebuild and canonical fee-policy suites.
- Verify APIs/UI keep realized, unrealized, and unsupported lifetime values
  distinct and disclose provisional fee status if VERIFY-013 remains open.

## Non-goals

Scanner ranking, portfolio sizing, dashboard presentation, or claiming lifetime
performance outside local coverage.

## Delivery and review

Functional summary explains which personal performance numbers are now reliable.
Keep it to the required 2-6 sentences and distinguish any provisional fee-based
results. Before delivery, update `CURRENT.md` to TKT-M16-01 or an explicit valid
handoff. Fresh flagship XHigh financial review required.
