# TKT-M19-04 - Build the Primary `What Should I Do?` Recommendation Screen

GitHub issue: #88

## Milestone

M19 - Core Recommendation Product

## Goal

Combine personal state, current orders, live market evidence, history, score,
and risk sizing into explicit manual actions that can be reviewed quickly.

## Functional outcome

The user can open one primary page and understand the best current manual
trading actions, prices/quantities, max-bid limits, historical confidence,
liquidity/risk evidence, and reasons within roughly one or two minutes.

## Dependencies

TKT-M16-01, TKT-M17-03, TKT-M19-01, TKT-M19-02, TKT-M19-03.

## Recommended Codex configuration

Risk class: **R3 (recommendation orchestration/financial)**.

- Implementation: Sol High preferred.
- Review: fresh flagship XHigh.

## Supported action vocabulary

`BUY`, `BUY SMALL`, `WAIT`, `KEEP BID`, `UPDATE BID`, `STOP BIDDING`,
`CANCEL BID`, `LIST`, `LEAVE SELL LISTING`, `HOLD`, `REDUCE`,
`SELL PARTIAL`, `SELL`, `SKIP`, `REVIEW`.

## Requirements

Each applicable action includes:

- item and quantity/capital;
- current buy/sell/order state;
- max allowed bid;
- exact modeled net profit/ROI;
- current depth/liquidity evidence;
- historical persistence/confidence/sample coverage;
- portfolio/risk impact;
- plain-language reasons.

Hard composition rules:

- never recommend bid above max bid;
- outbid alone does not imply chase/cancel;
- one-copper sell undercut alone does not imply cancel/relist;
- reserve/exposure constraints cannot be bypassed;
- insufficient evidence yields `WAIT`/`REVIEW`/`SKIP` rather than certainty;
- no action executes a TP mutation.

## Acceptance criteria

- [ ] Representative portfolio/order scenarios have deterministic regression tests.
- [ ] BUY/update/cancel/list/leave/hold/sell/skip states each have applicable coverage.
- [ ] UI consumes backend recommendation result rather than duplicating formulas.
- [ ] Reasons match actual component/constraint state.
- [ ] User can understand primary action list in ~1-2 minutes in usability review.
- [ ] No automated execution path exists.

## Validation

- Run deterministic portfolio/order/action regression vectors covering every
  applicable vocabulary state, max-bid, reserve/exposure, insufficient-
  evidence, outbid, relist, and no-mutation boundaries.
- Run backend API, frontend component/accessibility, and primary Playwright
  action-review journeys; verify React consumes backend results.
- Perform the documented 1-2 minute usability review and confirm displayed
  reasons match actual constraints/components.

## Non-goals

Trading Post mutation/automation, opaque recommendations, or outcome-based
self-modification.
