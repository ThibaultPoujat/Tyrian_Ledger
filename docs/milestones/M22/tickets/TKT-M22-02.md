# TKT-M22-02 - Harden Security, Recovery, E2E Coverage, Accessibility, and Local Packaging

GitHub issue: #96

## Milestone

M22 - Convenience, Hardening, and Evaluation

## Goal

Make the local-first application dependable for long-term daily use by a
non-programmer and re-audit all high-value boundaries after the feature set has
grown.

## Functional outcome

A clean supported machine can install/start the app from documentation, durable
state survives restart, backup/restore is proven on representative data,
critical workflows pass end-to-end, and secret/network/data failure states are
safe and understandable.

## Dependencies

TKT-M18-03, TKT-M19-04, TKT-M20-02, TKT-M20-03, TKT-M21-03, TKT-M22-01.

## Recommended Codex configuration

Risk class: **R3 (security/recovery/release)**.

- Implementation: Sol High preferred.
- Review: fresh flagship XHigh.

## Requirements

- Re-audit secret redaction/browser/network exposure.
- Confirm loopback default.
- Disaster-recovery exercise on populated DB.
- Clean-checkout install/start instructions for intentionally supported OSes.
- Simple launcher/command where practical.
- E2E for key status, sync, dashboard, scanner/watchlist, action screen,
  personal ranking, investments, crafting, alerts, restart persistence, and
  backup/restore.
- Accessibility regression for core UI.
- Safe understandable migration/recovery failure states.

## Acceptance criteria

- [ ] Clean supported machine can run from docs.
- [ ] No secret reaches browser assets/payloads/logs/repo/SQLite.
- [ ] Restart preserves durable state.
- [ ] Representative populated DB restores successfully.
- [ ] Critical E2E journey passes.
- [ ] Accessibility checks pass for core flow.
- [ ] Known limitations/support matrix documented.

## Validation

- Run the full .NET, frontend, workflow/script, and Playwright suites from a
  clean supported-machine/checkout setup.
- Run the complete TKT-M13-01 binding/Host/origin/anti-forgery integration suite,
  full-history Gitleaks scan, dependency/security audit, and browser-payload/log/
  SQLite secret checks.
- Exercise restart persistence, populated backup/restore/disaster recovery,
  migration failure, accessibility, and every user-facing journey named above.
- Verify supported packaging/install/start documentation end to end.

## Non-goals

New product features, LAN/Internet exposure, cloud hosting, or release/merge.

## Delivery and review

Functional summary explains how daily operation/recovery became dependable.
Keep it to the required 2-6 sentences. Before delivery, update `CURRENT.md` to
TKT-M22-03 or an explicit valid handoff. Fresh flagship XHigh security/release
review required.
