# TKT-M22-02 - Harden Security, Recovery, E2E Coverage, Accessibility, and Local Packaging

GitHub issue: #96

## Milestone

M22 - Convenience, Hardening, and Evaluation

## Goal

Make the local-first application dependable for long-term daily use by a non-programmer after the `Mes Signaux`/crafting/continuous-loop product shape is complete.

## Functional outcome

A clean supported machine can install/start the app from documentation, durable state survives restart, backup/restore is proven on representative data, critical `Mes Signaux`/`Artisanat`/`Réglages` journeys pass end to end, and secret/network/data failure states are safe and understandable.

## Dependencies

TKT-M18-03, TKT-M21-03 / #94, TKT-M22-01 / #95, TKT-M21-S03 / #131, TKT-M21-S05 / #133.

## Recommended Codex configuration

Risk class: **R3 (security/recovery/release)**.

Review path: **SOL-GATED** — Terra High implementation/fixes; Draft PR; full required validation/CI green before fresh separate Sol XHigh review; targeted fresh Sol re-review after scoped fixes.

## Requirements

- Re-audit secret redaction and browser/network exposure.
- Confirm safe loopback binding/Host/origin/anti-forgery boundaries.
- Full populated backup/restore disaster-recovery exercise.
- Clean-checkout install/start instructions for intentionally supported OSes.
- Provide a simple documented launcher/command where practical.
- End-to-end coverage for primary 0.1 journeys:
  - API/account status and sync;
  - `Mes Signaux` as default route;
  - navigation `Mes Signaux / Artisanat / Réglages`;
  - zero-signal and actionable-signal states;
  - `Pourquoi ?` progressive evidence;
  - truthful per-source freshness/degraded status;
  - 30d realized-performance headline with 7d/90d context and separate unrealized state;
  - Active/Passive start, current-step freeze, `Terminé`, Undo and material reconciliation conflict;
  - guided crafting-plan execution;
  - continuous-loop/actionable notification behavior;
  - restart persistence;
  - backup/restore.
- Accessibility regression for all core 0.1 surfaces.
- Database migration/recovery failure states are safe and understandable.
- User-facing labels/messages/errors/settings/accessibility copy exercised by release E2E are French.
- Legacy diagnostic/support routes intentionally retained after cleanup must not reappear as primary navigation.

## Acceptance criteria

- [ ] Fresh supported machine/clean checkout can run the app from documentation.
- [ ] No secret reaches browser assets/payloads/logs/repository/SQLite.
- [ ] Restart preserves intended durable state, including plan/shadow state where specified by its owning ticket.
- [ ] Representative populated database restores successfully.
- [ ] Critical `Mes Signaux` + `Artisanat` + `Réglages` E2E journey passes.
- [ ] Shadow/verified-state reconciliation and Undo have representative E2E coverage.
- [ ] Accessibility checks pass for the primary flow.
- [ ] French user-facing release copy has no accidental English regression in covered core journeys, except unavoidable proper nouns/technical identifiers explicitly allowed by UX policy.
- [ ] Known limitations/support matrix documented.

## Validation

- Full .NET, frontend, workflow/script and Playwright suites from a clean supported checkout.
- Complete binding/Host/origin/anti-forgery integration suite.
- Full-history secret scan, dependency/security audit and browser-payload/log/SQLite secret checks.
- Restart persistence and populated backup/restore/disaster-recovery exercise.
- Migration failure and accessibility regression tests.
- Verify all named 0.1 journeys and supported packaging/start documentation end to end.

## Non-goals

- New product features.
- LAN/Internet exposure or cloud hosting.
- Restoring superseded dashboard/scanner/investment pages to primary navigation.
- Release/merge itself.
