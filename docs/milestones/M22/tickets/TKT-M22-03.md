# TKT-M22-03 - Record and Evaluate Signal Plan Outcomes

GitHub issue: #97

## Milestone

M22 - Convenience, Hardening, and Evaluation

## Goal

Measure whether `Mes Signaux` and its deterministic plans actually help, using observed user-executed outcomes rather than trusting design assumptions or inventing counterfactual profit.

## Functional outcome

The application preserves enough versioned Signal/plan context to compare supported executed outcomes with modeled expectations, while keeping ignored/unexecuted suggestions explicitly unobserved and preserving additive realized-performance attribution.

## Dependencies

TKT-M20-02, TKT-M21-03 / #94, TKT-M22-02 / #96, TKT-M21-S05 / #133.

## Recommended Codex configuration

Risk class: **R3 (quantitative/evaluation)**.

Review path: **NORMAL** with Terra High independent review/check unless explicitly escalated under `docs/workflow/model-effort-guide.md`.

## Requirements

Persist/version enough context to reproduce a Signal/plan decision:

- timestamp;
- originating opportunity/strategy class;
- plan and ordered steps;
- selected action/quantity/price bounds;
- modeled economics and confidence;
- score/utility components and binding constraints;
- capital/inventory/resource reservations;
- relevant current/historical/personal evidence;
- configuration/rules version;
- whether the user started the plan;
- locally recorded step-completion events and later verified reconciliation state where applicable.

Evaluate only where evidence supports observation:

- realized result versus modeled result;
- capital lock duration and turnover;
- completion/abandon/reconciliation outcomes where actually observable;
- low-liquidity/false-positive patterns;
- plan replacement/invalidation frequency;
- confidence/utility calibration by bucket where sample size is sufficient;
- simple defensible benchmark comparisons.

## Strategy attribution

- Realized headline categories are additive and non-overlapping for the same supported population/window: `Trading/Flipping`, `Crafting`, `Unclassified`.
- Ambiguous results remain `Unclassified`; do not interrupt the user merely to force a label.
- Later deterministic evidence may reclassify an outcome when justified.
- `Crafting value added` may be reported on `Artisanat` as value created versus the best realistic input alternative, but it must not be added again to global realized profit.
- Open/unrealized results remain separate from realized results.

## Acceptance criteria

- [ ] Historical Signal/plan context remains reproducible after future rule changes.
- [ ] Started/executed plans are distinguished from unexecuted suggestions.
- [ ] No counterfactual profit is fabricated for a plan the user never executed.
- [ ] Shadow/local execution evidence and later verified evidence are not double-counted.
- [ ] Trading/Crafting/Unclassified realized categories sum consistently to realized total for the same supported population/window.
- [ ] Crafting value-added reporting cannot double-count realized profit.
- [ ] Reports can identify weak strategies/components without automatically changing rules or weights.
- [ ] Insufficient sample size/coverage is explicit.
- [ ] Private evaluation remains local-first.

## Validation

- Versioning/migration and old-context replay tests.
- Started/executed versus ignored/unexecuted tests.
- Shadow-versus-verified reconciliation/double-counting tests.
- Strategy attribution reconciliation tests across supported windows.
- Calibration/benchmark tests with explicit insufficient-sample behavior.
- Relevant recommendation/accounting/personal-ranking regression suites.

## Non-goals

- Automatic self-modification of ranking/weights.
- Fabricated outcomes for ignored/unexecuted Signals.
- Public sharing/cloud analytics of private performance.
- Reintroducing investment discovery into 0.1.
