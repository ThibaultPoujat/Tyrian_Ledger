# TKT-M18-03 - Add Market-History Retention, Integrity, Storage Statistics, and Backup Coverage

GitHub issue: #84

## Milestone

M18 - Owned Historical Market Dataset

## Goal

Keep months of market collection sustainable and recoverable without silently
destroying unique evidence.

## Functional outcome

The user can inspect history coverage/storage size, trust basic integrity checks,
and know backups include market history; any retention/downsampling policy is
explicit, deterministic, and safe.

## Dependencies

TKT-M14-03, TKT-M18-02.

## Recommended Codex configuration

Risk class: **R3 (retention/destructive data)**.

- Implementation: Sol High preferred.
- Review: fresh flagship XHigh.

## Requirements

- Separate retention policy for cheap best-price versus detailed book data.
- Preserve recent/high-value raw evidence; any downsampling is documented/versioned.
- Integrity checks for impossible values, duplicates, timestamp/schema consistency.
- Include history in backup/restore verification.
- Expose simple storage and coverage statistics.

## Acceptance criteria

- [ ] No retention operation silently destroys the only copy outside explicit approved policy.
- [ ] Downsampling, if implemented, is deterministic/tested and preserves documented aggregates/raw windows.
- [ ] Backup/restore round trip includes representative market history.
- [ ] Storage usage and per-item/window coverage can be inspected.
- [ ] Duplicate/malformed historical observation tests exist.
- [ ] Clear-personal-data behavior remains distinct from public history where designed.

## Delivery and review

Functional summary describes how growing history is protected/managed. Fresh
flagship XHigh destructive-data review required.
