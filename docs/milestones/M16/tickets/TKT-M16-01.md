# TKT-M16-01 - Build the Personal Dashboard and Current-Order Views

GitHub issue: #78

## Milestone

M16 - Personal Dashboard and Current Orders

## Goal

Expose the account/accounting foundation through a useful accessible React UI
before adding scanner/recommendation complexity.

## Functional outcome

The user can open Tyrian Ledger and see connection/sync status, history coverage,
7/30/90 realized performance, open/unrealized state, capital in current buys,
current sell listings, recent trades, and current-order market comparison.

## Dependencies

TKT-M13-01, TKT-M14-02, TKT-M15-03.

## Recommended Codex configuration

Risk class: **R2**.

- Implementation: Terra High or Sol High.
- Review: fresh Sol High.

## Requirements

- Local API returns structured backend-authoritative dashboard/order values.
- React has loading/error/empty/unknown states.
- No duplicate fee/P&L formula in browser.
- Key never reaches browser.
- Current orders show item, quantity, order price and current market comparison.
- Personal results disclose coverage/unknown basis.

## Acceptance criteria

- [ ] 7/30/90 realized values render from backend result models.
- [ ] Open/unrealized state is labeled separately.
- [ ] Current buy/sell orders are visible with useful market context.
- [ ] Insufficient/unknown history states are understandable.
- [ ] Accessibility/component tests cover primary states.
- [ ] No scanner/full recommendation behavior is added.

## Validation

- Run backend dashboard/order query tests for 7/30/90, open/unrealized,
  current-order, coverage, and unknown-basis states.
- Run frontend component/accessibility tests for loading, error, empty, unknown,
  and populated states plus relevant Playwright journeys.
- Verify browser bundles contain no fee/P&L formula or API key material.

## Non-goals

Scanner ranking, historical analytics, final recommendations, or browser-side
financial calculations.

## Delivery and review

Functional summary should describe what the user can now understand without a
spreadsheet in the required 2-6 sentences. Before delivery, update `CURRENT.md`
to TKT-M17-01 or an explicit valid handoff. Fresh review checks financial-value
ownership remains backend-side.
